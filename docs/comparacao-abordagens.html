Comparação de Abordagens — Schema para Perfis

Escolha como os dados de Pessoal, Empresarial e Kommo serão armazenados no banco

✦ Recomendado
Opção A
Colunas adicionais na tabela transactions
-- tabela atual + novos campos
transactions
  id, user_id, title
  amount, type, date, notes
  perfil            text -- novo
  nome_cliente     text?
  nome_empresa     text?
  divisao_socio    numeric?
  plano            int?
  num_usuarios     int?
  valor_liquido    numeric?
  divisao_pct      numeric?
  prolabore        numeric?

-- tabela para pró-labore mensal
empresarial_config
  user_id, mes    text
  prolabore      numeric
Query — filtrar perfil Kommo
select * from transactions
where perfil = 'kommo'
  and user_id = auth.uid()
Prós e contras
✅ Uma tabela, queries simples e diretas
✅ Hooks existentes funcionam com pequenos ajustes
✅ TypeScript tipado campo a campo
⚠️ ~10 colunas nullable (aceitável para 3 perfis fixos)
Simples Rápido Tipado
Opção B
Coluna JSONB metadata
-- schema enxuto
transactions
  id, user_id, title
  amount, type, date, notes
  perfil      text
  metadata    jsonb

-- exemplos de metadata
-- Empresarial:
{ nome_cliente: "...",
  divisao_socio: 500 }

-- Kommo:
{ plano: 12,
  num_usuarios: 3,
  divisao_pct: 50 }
Query — soma campo de JSONB
select
  sum((metadata->>
    'divisao_socio')::numeric)
from transactions
where perfil = 'empresarial'
Prós e contras
✅ Schema enxuto, fácil de evoluir
✅ Novos campos sem nova migration
⚠️ Queries com cast explícito (menos ergonômico)
❌ Sem type safety no TypeScript sem mapeamento manual
❌ Mais difícil de indexar e filtrar
Flexível Queries verbosas Sem tipos
Opção C
Tabelas separadas por perfil
-- 3 tabelas independentes
transactions_pessoal
  id, user_id, title
  amount, type, date, notes

transactions_empresarial
  id, user_id
  nome_cliente, nome_empresa
  faturamento, divisao_socio
  type, date, notes

transactions_kommo
  id, user_id
  nome_cliente, nome_empresa
  plano, num_usuarios
  valor_total, valor_liquido
  divisao_pct, date
Query — ver todas as transações
select * from transactions_pessoal union all select ...from transactions_empresarial union all select ...from transactions_kommo
Prós e contras
✅ Schema perfeitamente limpo por perfil
❌ Quebra todos os hooks e páginas existentes
❌ UNION ALL obrigatório para visão consolidada
❌ 3× mais migrations, RLS policies e hooks
❌ Muito trabalho extra sem benefício real
Schema limpo Complexo Quebra tudo
